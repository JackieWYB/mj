# 《卡五星微信小游戏》完整功能清单 + 验收用例大纲

> 角色视角：制作人 + 测试负责人。
> 说明：每个功能包含“用户故事、前置条件、主流程、异常流程、验收标准”。

---

## 1. 账号/登录
- **用户故事**：玩家首次进入可快速登录并进入大厅，老玩家可无感续登。
- **前置条件**：微信授权能力可用；账号服务可用。
- **主流程**：
  - 打开小程序/小游戏 -> 拉起微信登录 -> 服务端换取 token -> 进入大厅。
- **异常流程**：
  - 授权拒绝、token 过期、服务端超时。
- **验收标准**：
  - 首登成功率 >= 99%；token 过期能自动跳转重登；错误文案明确且可重试。

## 2. 大厅
- **用户故事**：玩家在大厅可看到核心入口（快速开始/创建房间/加入房间/俱乐部/活动/商城/战绩）。
- **前置条件**：登录成功。
- **主流程**：
  - 拉取首页数据（公告、活动入口、资产、常用玩法）-> 点击进入对应模块。
- **异常流程**：
  - 首页接口失败、配置缺失、活动已下线。
- **验收标准**：
  - 入口可达率 100%；加载态/空态/错误态齐全；首页 P95 首屏 < 2s。

## 3. 匹配（快速/段位）
- **用户故事**：玩家可发起快速匹配并在合理时间进入对局。
- **前置条件**：在大厅；账号状态正常未封禁。
- **主流程**：
  - 点击快速开始 -> 入队 -> 匹配成功 -> 自动进房。
- **异常流程**：
  - 匹配超时、取消匹配、风控限流、网络波动。
- **验收标准**：
  - 取消匹配即时生效；超时有提示与重试；匹配成功后 roomId 正确。

## 4. 好友房（创建/加入）
- **用户故事**：玩家创建房间并通过房号邀请好友。
- **前置条件**：大厅可用；房规配置可用。
- **主流程**：
  - 创建房间 -> 生成房号 -> 好友输入房号加入 -> 满员开局。
- **异常流程**：
  - 房号不存在、房间已满、房间已开局、频繁建房限流。
- **验收标准**：
  - 房号唯一且可查询；错误码与提示一致；开局前座位状态同步一致。

## 5. 俱乐部
- **用户故事**：玩家可加入俱乐部并在俱乐部内组织对局。
- **前置条件**：俱乐部功能开启。
- **主流程**：
  - 进入俱乐部 -> 查看成员/房间 -> 发起或加入俱乐部房。
- **异常流程**：
  - 非成员访问、权限不足、俱乐部禁赛。
- **验收标准**：
  - 权限控制正确（管理员/成员）；俱乐部房对局可追溯到俱乐部维度。

## 6. 对局（全流程）
- **用户故事**：玩家完整体验发牌->摸打->吃碰杠胡->结算。
- **前置条件**：房间人数满足；规则加载成功。
- **主流程**：
  - 准备 -> 开始发牌 -> 回合轮转 -> 操作（吃碰杠胡过）-> 胡牌/流局 -> 结算。
- **异常流程**：
  - 非法操作、超时未操作、客户端重复 action、规则冲突。
- **验收标准**：
  - 服务端权威裁定；事件 seq 连续；结算分与回放一致。

### 6.1 状态一致性专项
- **用户故事**：弱网下所有玩家看到同一局面。
- **前置条件**：事件同步链路可用。
- **主流程**：
  - 正常广播 -> 客户端按 seq 应用 -> ack。
- **异常流程**：
  - 丢包、乱序、重复包。
- **验收标准**：
  - 丢包可补；乱序可缓存；重复包不重复执行；状态哈希一致。

### 6.2 按钮可用性（吃碰杠胡过）
- **用户故事**：只在合法时机显示可操作按钮。
- **前置条件**：服务端下发可操作集合。
- **主流程**：
  - 收到可操作集 -> 前端展示对应按钮 -> 点击后上报意图。
- **异常流程**：
  - 按钮误显、越权点击、延迟导致过期操作。
- **验收标准**：
  - 按钮显示与服务端可操作集合 100% 一致；过期操作正确拒绝。

### 6.3 倒计时
- **用户故事**：玩家清楚剩余决策时间。
- **前置条件**：服务端下发回合起始时间与时长。
- **主流程**：
  - 开始倒计时 -> 到时自动 PASS/托管。
- **异常流程**：
  - 前后端时间漂移、倒计时卡住。
- **验收标准**：
  - 客户端展示误差 <= 300ms；超时动作与服务端一致。

### 6.4 托管（可选）
- **用户故事**：断线或主动托管后系统代打，恢复可取消。
- **前置条件**：托管策略开启。
- **主流程**：
  - 玩家启用托管/超时触发托管 -> 系统代操作 -> 玩家取消托管。
- **异常流程**：
  - 频繁切换托管、托管状态不同步。
- **验收标准**：
  - 托管状态广播一致；托管行为可审计。

### 6.5 逃跑惩罚（可配置）
- **用户故事**：恶意中途退出会受惩罚，保证对局公平。
- **前置条件**：惩罚策略已配置。
- **主流程**：
  - 对局中退出 -> 记逃跑次数 -> 触发扣分/限匹配。
- **异常流程**：
  - 弱网误判、重连成功后仍处罚。
- **验收标准**：
  - 区分恶意与网络异常；处罚规则可配置可回溯。

## 7. 断线重连
- **用户故事**：断线后可恢复到当前局面继续游戏。
- **前置条件**：重连协议可用（snapshot+delta）。
- **主流程**：
  - 断线 -> 重连鉴权 -> 拉快照 -> 补增量 -> 恢复操作。
- **异常流程**：
  - 房间已结束、房间不存在、被踢、多端登录挤号。
- **验收标准**：
  - 重连成功后局面一致；异常场景提示准确并正确跳转。

## 8. 聊天/表情
- **用户故事**：玩家可在局内发送快捷语与表情。
- **前置条件**：房间内。
- **主流程**：
  - 发送文本/表情 -> 服务端广播 -> 全员展示。
- **异常流程**：
  - 频率过高、敏感词、网络延迟。
- **验收标准**：
  - 限频生效；敏感词策略生效；显示不阻塞主流程。

## 9. 战绩列表
- **用户故事**：玩家可查看近期对局结果。
- **前置条件**：已登录。
- **主流程**：
  - 拉取分页列表 -> 下拉加载更多 -> 点击进入详情。
- **异常流程**：
  - 空列表、分页重复、接口失败。
- **验收标准**：
  - 分页无重无漏；空态/错误态正确。

## 10. 战绩详情
- **用户故事**：玩家可查看某局详情和分数构成。
- **前置条件**：战绩存在。
- **主流程**：
  - 打开详情 -> 展示玩家、番型、分数变化 -> 可跳回放。
- **异常流程**：
  - 记录不存在、权限不足。
- **验收标准**：
  - 数据与结算一致；权限控制正确。

## 11. 回放入口与播放
- **用户故事**：玩家可重看完整对局过程。
- **前置条件**：回放文件可访问。
- **主流程**：
  - 打开回放 -> 加载事件流 -> 播放/暂停/倍速/跳转。
- **异常流程**：
  - 回放未生成、文件损坏、无权限。
- **验收标准**：
  - 播放结果与战绩一致；权限策略生效（参与者/管理员）。

## 12. 设置
- **用户故事**：玩家可调整音效、震动、画质偏好。
- **前置条件**：客户端设置模块可用。
- **主流程**：
  - 修改设置 -> 即时生效 -> 本地持久化。
- **异常流程**：
  - 设置项读取失败、版本不兼容。
- **验收标准**：
  - 重启后设置保留；不影响对局逻辑。

## 13. 公告/客服
- **用户故事**：玩家能查看公告并联系在线客服。
- **前置条件**：公告系统/客服入口可用。
- **主流程**：
  - 打开公告 -> 查看内容 -> 点击客服。
- **异常流程**：
  - 公告加载失败、客服不可用。
- **验收标准**：
  - 至少保底展示最近公告；客服不可用时有替代引导。

## 14. 商城/付费
- **用户故事**：玩家可购买道具并到账。
- **前置条件**：商品与支付配置有效。
- **主流程**：
  - 选商品 -> 创建订单 -> 微信支付 -> 回调验签 -> 发货到账。
- **异常流程**：
  - 支付取消、回调延迟、重复回调、发货失败。
- **验收标准**：
  - 订单状态机正确；重复回调幂等；到账可对账。

## 15. 活动入口
- **用户故事**：玩家可查看活动并领取奖励。
- **前置条件**：活动配置发布。
- **主流程**：
  - 进入活动页 -> 查看任务 -> 达成后领取奖励。
- **异常流程**：
  - 活动过期、重复领取、配置错误。
- **验收标准**：
  - 奖励幂等发放；活动时间窗严格生效。

## 16. 三阶段范围划分

## MVP（可内测）
- 登录、基础大厅
- 快速匹配 + 好友房（基础房规）
- 对局全流程（吃碰杠胡过、倒计时）
- 断线重连（snapshot+delta）
- 战绩列表/详情（基础）
- 基础设置（音效）

## 公测
- 俱乐部
- 回放播放（倍速/暂停/跳转）
- 聊天表情
- 公告客服
- 活动入口
- 托管 + 逃跑惩罚（配置化）
- 商城支付基础闭环

## 正式（商业化）
- 完整风控分级与处置自动化
- 支付对账与异常补偿闭环
- 精细化运营活动（任务、礼包、AB）
- 俱乐部管理增强（权限、战队数据）
- 回放审计与举报联动
