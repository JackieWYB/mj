# 卡五星麻将：基础可用反作弊与风控方案

> 目标：在“服务端权威”前提下，建立可上线的基础风控闭环（检测-分级-处置-审计）。

## 0) 核心原则
- 发牌/摸牌/可操作集合/算分全部由服务端执行。
- 客户端只上报“意图动作”，不接受客户端胜负与算分结论。
- 所有风控结论都可审计（有日志、有证据、有回放）。

---

## 1) 风控指标与阈值建议（默认值）

## 1.1 实时限频（登录/匹配/房间）
| 场景 | 维度 | 阈值（默认） | 处置 |
|---|---|---:|---|
| 登录请求 | uid/device/ip | 10次/分钟 | 超限返回 `RATE_LIMITED_LOGIN` |
| 匹配请求 | uid | 20次/分钟 | 限流 60 秒 |
| 创建房间 | uid | 10次/小时 | 限流 + 黄级标记 |
| 加入房间 | uid | 60次/小时 | 限流 |
| 退出/解散 | uid | 30次/小时 | 限流 + 可疑标记 |
| 聊天/表情 | uid | 30次/分钟 | 限流 |

## 1.2 连接行为（断线/重连）
| 指标 | 默认阈值 | 说明 |
|---|---:|---|
| 重连次数 | > 15次/10分钟 | 高于阈值记黄级 |
| 心跳超时率 | > 30%/局 | 联合网络质量判断 |
| 频繁秒断线 | >= 8次/10分钟 | 疑似脚本/代理切换 |
| 多端并发同账号 | >=2 活跃连接持续30秒 | 触发挤号/红级 |

## 1.3 对局作弊检测（离线+准实时）
| 指标 | 建议阈值 | 触发等级 |
|---|---:|---|
| 异常胜率 | 最近100局胜率 > 75% 且显著偏离同段位 | 黄/红 |
| 异常胡牌速度 | 平均决策时长 < 0.8s 且稳定异常 | 黄 |
| 固定搭子 | 与同2~3人同桌占比 > 60% | 黄 |
| 输赢相关性 | 双人分差相关系数绝对值 > 0.85 | 红候选 |
| 短局频繁 | 5分钟内多局异常结束 > 8局 | 黄 |
| 同IP/同设备关联 | 同设备多账号 + 高重叠同桌 | 红候选 |

> 注：阈值应按真实分布逐步校准，先“宽松告警”再“严格处置”。

## 2) Redis 限流 key 设计

## 2.1 通用规则
- Key 结构：`risk:rate:{scope}:{id}:{action}:{window}`
- Value：计数器（INCR）
- TTL：窗口长度（秒）

## 2.2 示例
- 登录：`risk:rate:uid:{uid}:login:60`
- 登录设备：`risk:rate:device:{deviceId}:login:60`
- 匹配：`risk:rate:uid:{uid}:match:60`
- 建房：`risk:rate:uid:{uid}:room_create:3600`
- 加房：`risk:rate:uid:{uid}:room_join:3600`
- 重连：`risk:rate:uid:{uid}:reconnect:600`
- 心跳超时：`risk:metric:uid:{uid}:heartbeat_timeout:600`
- 多端会话：`risk:session:uid:{uid}` -> 当前连接集合
- 设备多账号：`risk:device:{deviceId}:uids` -> set
- 黑名单：`risk:blacklist:uid:{uid}`
- 灰名单：`risk:greylist:uid:{uid}`

## 3) 采集的客户端信息字段（合规最小集）

> 原则：最小必要、目的明确、不采集敏感个人隐私。

## 3.1 设备与环境（微信生态可获取）
- `deviceModel`（机型）
- `osType`（iOS/Android）
- `osVersion`
- `appVersion`（小游戏版本）
- `sdkVersion`（微信基础库）
- `networkType`（wifi/4g/5g/unknown）
- `scene`（启动场景值）
- `clientTs`（客户端时间戳）
- `installId`（应用内生成匿名安装标识）

## 3.2 会话与行为
- `uid`
- `sessionId`
- `roomId`
- `actionId/actionType`
- `rttMs`（网络往返估算）
- `disconnectReason`（可用时）
- `reconnectCount`

## 3.3 不建议采集
- 精确地理位置
- 通讯录、短信、相册等与业务无关隐私
- 可识别个人身份的敏感信息（超业务必要范围）

## 4) 风险等级与处置策略

| 风险等级 | 判定方式 | 处置策略 |
|---|---|---|
| 绿（正常） | 无异常或低风险 | 正常放行 |
| 黄（可疑） | 单项指标超阈值/轻度组合异常 | 提示、限频、限制匹配模式、人工复核 |
| 红（高危） | 多维强相关异常/明确作弊证据 | 临时禁赛、封禁、设备封禁、俱乐部隔离 |

### 4.1 处置动作优先级
1. `WARN`：仅提示
2. `THROTTLE`：限流
3. `MATCH_RESTRICT`：限制匹配
4. `TEMP_BAN`：临时禁赛（1h/24h/72h）
5. `PERM_BAN`：永久封禁（需人工复核或强证据）

## 5) 日志字段标准与审计

## 5.1 风控事件日志（结构化）
```json
{
  "ts": 1730000000000,
  "traceId": "tr_xxx",
  "uid": "U1001",
  "roomId": "R2002",
  "roundId": "RD3003",
  "action": "room_create",
  "riskType": "RATE_LIMIT",
  "riskScore": 78,
  "riskLevel": "YELLOW",
  "ruleId": "RL_LOGIN_001",
  "decision": "THROTTLE",
  "deviceId": "did_xxx",
  "ipHash": "sha256_xxx",
  "evidence": {"count": 35, "windowSec": 60}
}
```

## 5.2 审计要求
- 风控命中必须可追溯：规则版本、阈值、证据快照。
- 封禁/解封必须有操作者与理由。
- 回放ID与战绩ID关联，支持复核。

---

## 6) 管理后台最小功能清单

1. **风险查询**
   - 按 uid/roomId/deviceId/time 查询风险事件
   - 支持风险等级、规则ID筛选
2. **用户画像卡片**
   - 最近局数、胜率、重连次数、同桌关系图谱摘要
3. **标记管理**
   - 绿/黄/红人工标记
   - 备注与生效时长
4. **处罚管理**
   - 临时禁赛、永久封禁、解封
   - 批量导入导出（运维）
5. **规则配置**
   - 阈值调参、灰度生效、回滚
6. **审计日志**
   - 谁在何时做了什么风控操作

---

## 7) 上线建议（基础可用）
1. 第1周：仅采集 + 告警，不自动封禁。
2. 第2周：对明确限频场景启用自动 `THROTTLE`。
3. 第3周：引入黄/红分级与人工复核流程。
4. 第4周：对“强证据组合”启用 `TEMP_BAN`。
